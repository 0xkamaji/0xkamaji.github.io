Looking at the section headers and imported functions via PE-Bear (or CFF Explorer) we see that there are minimal imports and typical sections missing. The one dll imported is mscoree.dll:  
	```
	Mscoree.dll is a Microsoft library file that is part of the Microsoft .NET Framework, essential for running applications that use managed code. It is located in the C:\Windows\System32 folder and is required for the execution of .NET applications. 
	```
We also see in the Data Directories a ".NET Header" with an address and size and, when I attempted to debug the binary I was prompted to install a .Net framework. These all pointed me towards this being a .NET binary which I therefore loaded in `dnSpy`.

Pretty quickly I came across the following function `btnDecode_Click()`:

```
// XXXXXXXXXXXXXXX.Form1
// Token: 0x06000002 RID: 2 RVA: 0x00002060 File Offset: 0x00000260
private void btnDecode_Click(object sender, EventArgs e)
{
	this.pbRoge.Image = Resources.bob_roge;
	byte[] dat_secret = Resources.dat_secret;
	string text = "";
	foreach (byte b in dat_secret)
	{
		text += (char)(((b >> 4) | (((int)b << 4) & 240)) ^ 41);
	}
	text += "\0";
	string text2 = "";
	for (int j = 0; j < text.Length; j += 2)
	{
		text2 += text[j + 1];
		text2 += text[j];
	}
	string text3 = "";
	for (int k = 0; k < text2.Length; k++)
	{
		char c = text2[k];
		text3 += (char)((byte)text2[k] ^ 102);
	}
	this.lbl_title.Text = text3;
}
```

This function appears to access a stored resource named dat_secret and enters into a decoding loop. The function has 3 separate loops the takes the result of each loop and feeds it into the next.

I set a breakpoint at the beginnning of this function and after moving through the first loop a few times I set a breakpoint at the end of this function. When I continue to this point I can see all three variables, text, text2 and text 3 populated.
